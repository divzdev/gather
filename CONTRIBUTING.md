# Contributing

## Setup

```bash
make setup && make dev
```

If that doesn't work on a clean machine, that's a bug worth reporting on its own.

## Before opening a PR

```bash
make lint   # ruff, mypy --strict, tsc, eslint — must be clean
make test   # must be green
```

CI runs the same commands plus a migration round-trip (`upgrade → check →
downgrade → upgrade`), so a migration that doesn't reverse cleanly fails there.

## Conventions

- **Commits:** [Conventional Commits](https://www.conventionalcommits.org/) —
  `feat:`, `fix:`, `chore:`, `refactor:`, `test:`, `docs:`.
- **Branches:** short-lived, off `main`.
- **PRs:** small and single-purpose.

## Things that will get a PR sent back

- **A new abstraction with one caller.** Interfaces, wrappers and layers are added
  at the second real usage, not in anticipation of one.
- **A hardcoded colour, spacing value, or type size** in the frontend. Everything
  comes from the design tokens.
- **A hand-written type describing an API response.** `apps/web/src/lib/api-types.ts`
  is generated by `make types`.
- **A bulk `update()`/`delete()` without a tenant predicate.** A guard raises on
  these, because `with_loader_criteria` does not cover Core statements. Add the
  predicate; don't weaken the guard.
- **A migration whose `downgrade()` leaves enum types behind.** Autogenerate drops
  tables but never the enums it created, and the orphans break the next upgrade.
- **An SSE endpoint that takes the `get_db` dependency.** It would hold a database
  connection for the whole model call. See `docs/ARCHITECTURE.md`.

## Where to look

`docs/ARCHITECTURE.md` for how the system fits together and why, `docs/APP_CONTEXT.md`
for the domain rules, `docs/DECISIONS.md` for calls already made and the
alternatives rejected. If you're about to do something the docs argue against,
that's worth a conversation first — but the docs are wrong sometimes, and saying
so with a reason is welcome.
